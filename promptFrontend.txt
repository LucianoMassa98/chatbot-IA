================================================================================
  PROMPT PARA FRONTEND — YEMAS DEL SOL CRM
  Stack: Vite + React.js + Tailwind CSS
  Fecha: Julio 2026 — v2.0 (Gestión de Suscripciones)
================================================================================

Necesito que crees una aplicación frontend CRM/Admin para "Yemas del Sol", una
empresa argentina de venta de maples de huevos frescos con delivery.

La app se conecta a un backend Node.js/Express existente. Todos los endpoints
están protegidos con Google OAuth (Bearer token) excepto el login.

STACK OBLIGATORIO:
- Vite como bundler
- React.js (con hooks, functional components)
- Tailwind CSS para estilos
- React Router v6 para navegación
- Axios para HTTP requests
- @react-oauth/google para autenticación Google
- Lucide React o React Icons para iconos
- Recharts para gráficos del dashboard

================================================================================
  1. AUTENTICACIÓN — Google OAuth
================================================================================

Endpoint: POST /api/auth/google
Body: { idToken: "<Google ID token>" }
Response 200: { success: true, user: { id, email, role, firstName, picture } }
Response 403: Usuario no registrado

FLUJO:
1. El usuario hace clic en "Iniciar sesión con Google"
2. Google devuelve un ID token
3. Se envía el token al backend POST /api/auth/google
4. Si es exitoso, se guarda el token y los datos del usuario en Context/localStorage
5. Todas las requests posteriores van con header: Authorization: Bearer <idToken>
6. IMPORTANTE: el backend acepta roles "armador", "repartidor" y "administrador"
7. CRM_FRONTEND_URL en el backend está en http://localhost:5173

VARIABLE DE ENTORNO (poner en .env del frontend):
  VITE_GOOGLE_CLIENT_ID=<tu Google Client ID>
  VITE_API_URL=http://localhost:3000

  2. MODELOS DE DATOS (para entender las entidades)
================================================================================

USER:
  - id: UUID
  - contact: string (teléfono WhatsApp)
  - channel: "whatsapp"
  - role: "cliente" | "armador" | "repartidor" | "administrador"
  - firstName, lastName: string
  - address: string
  - location: { lat, lng, googleMapsUrl }
  - deliverySchedule: { morning, afternoon, evening }
  - isActive: boolean
  - metadata: JSON (incluye googleEmail para staff)

PRODUCT:
  - id: UUID
  - name: string (ej. "Maple de 30 huevos")
  - description: text
  - price: decimal
  - quantity: integer (default 1)
  - unit: string ("maple", "docena", "unidad")
  - isActive: boolean

SUBSCRIPTION (plan de suscripción):
  - id: UUID
  - name: string (ej. "Plan Familiar")
  - description: text
  - maplesQuantity: integer
  - frequency: "weekly" | "biweekly" | "monthly"
  - price: decimal
  - isActive: boolean

USER_SUBSCRIPTION (instancia activa de suscripción de un cliente):
  - id: UUID
  - userId: UUID → User (el cliente)
  - subscriptionId: UUID → Subscription (el plan)
  - status: "pending_payment" | "active" | "paused" | "expired" | "cancelled"
  - currentPeriodStart: datetime (inicio del mes en curso)
  - currentPeriodEnd: datetime (fecha de renovación)
  - nextDeliveryDate: datetime (próxima entrega semanal/quincenal)
  - deliveryCount: integer (entregas realizadas en el período)
  - renewalOrderId: UUID (orden de pago de renovación pendiente, si existe)
  - reminderSentAt: datetime
  - cancelledAt: datetime
  - metadata: JSON (deliveryOrderIds: lista de IDs de órdenes de entrega)
  - user: { firstName, lastName, contact, address }
  - plan: { name, price, frequency, maplesQuantity }
  - deliveryOrders: [ { id, status, quantity, estimatedDelivery, deliveredAt } ]

ORDER:
  - id: UUID
  - userId: UUID (→ User)
  - productId: UUID (→ Product, nullable)
  - subscriptionId: UUID (→ Subscription, nullable)
  - type: "single" | "subscription"
  - status: "pending_payment" | "paid" | "preparing" | "ready" | "delivering" | "delivered" | "rescheduled" | "cancelled"
  - quantity: integer
  - total: decimal (en ARS, puede ser 0 para entregas de suscripción)
  - deliveryAddress: string
  - estimatedDelivery: datetime
  - deliveredAt: datetime
  - notes: text
  - metadata: { isRenewal, userSubscriptionId, isWeeklyDelivery, deliveryNumber }

PAYMENT:
  - id: UUID
  - orderId: UUID
  - mercadoPagoId: string
  - preferenceId: string
  - paymentLink: URL
  - status: "pending" | "approved" | "rejected" | "cancelled"
  - amount: decimal

ORDER_ASSIGNMENT:
  - id: UUID
  - orderId: UUID
  - operatorId: UUID (→ User)
  - role: "armador" | "repartidor" | "ambos"
  - status: "assigned" | "in_progress" | "completed"
  - assignedAt, startedAt, completedAt: datetime
  - notes: text

DELIVERY_ZONE:
  - id: UUID
  - name: string (ej. "Zona Norte")
  - description: text
  - centerLat, centerLng: decimal
  - radiusKm: decimal
  - localities: JSON array
  - isActive: boolean

OPERATING_HOURS:
  - id: UUID
  - dayOfWeek: 0-6 (0=Domingo)
  - openTime, closeTime: TIME (ej. "08:00:00")
  - deliveryStartTime, deliveryEndTime: TIME
  - isActive: boolean

  3. API ENDPOINTS COMPLETOS
================================================================================

BASE URL: http://localhost:3000
Todas las rutas protegidas requieren: Authorization: Bearer <google_id_token>

─── AUTH (público) ───────────────────────────────────────────
POST   /api/auth/google                    { idToken }

─── CRM CHAT (operador + admin) ─────────────────────────────
GET    /api/conversations                  → lista todas las conversaciones
GET    /api/conversations/:id/messages     → mensajes de una conversación
POST   /api/conversations/:id/messages     { content } → enviar mensaje al cliente
PUT    /api/conversations/:id/status       { status: "active"|"closed"|"waiting" }

─── DASHBOARD / REPORTES (operador + admin) ─────────────────
GET    /api/reports/summary                → métricas: clientes totales, pedidos hoy, pagos pendientes, en reparto, entregados
GET    /api/reports/deliveries             → despachos del día

─── PEDIDOS (operador + admin) ──────────────────────────────
GET    /api/orders                         ?status=<filtro> → lista pedidos (últimos 200)
GET    /api/orders/:id                     → detalle del pedido con cliente, producto, pago
PUT    /api/orders/:id/status              { status, notes? } → cambiar estado
GET    /api/orders/pending-assignment      ?role=armador|repartidor → pedidos pendientes de asignación
POST   /api/orders/:id/assign             { operatorId, role } → asignar operador
POST   /api/orders/:id/self-assign        { role } → auto-asignarse
PUT    /api/orders/:id/complete-armado     { notes? } → armador confirma armado
PUT    /api/orders/:id/complete-entrega    { notes? } → repartidor confirma entrega
GET    /api/orders/:id/assignments         → historial de asignaciones

─── MIS ASIGNACIONES (operador + admin) ─────────────────────
GET    /api/my-assignments                 → asignaciones activas del operador logueado
GET    /api/my-assignments/history         ?limit=50 → historial completo

─── CLIENTES (operador + admin) ─────────────────────────────
GET    /api/clients                        → lista de clientes (role=cliente)
GET    /api/clients/:id                    → perfil + historial de pedidos
GET    /api/clients/:id/subscriptions      → suscripciones de un cliente (activas e históricas)

─── SUSCRIPCIONES ACTIVAS DE CLIENTES — USER SUBSCRIPTIONS ──
    Consulta (operador + admin):
GET    /api/user-subscriptions             ?status=active|paused|expired|cancelled|pending_payment
                                           → lista todas las suscripciones activas de clientes

    Administración (solo admin):
GET    /api/user-subscriptions/:id         → detalle de suscripción + historial de entregas
PUT    /api/user-subscriptions/:id/cancel  { notes? } → cancelar suscripción + notifica al cliente
PUT    /api/user-subscriptions/:id/pause   → pausar (detiene entregas semanales)
PUT    /api/user-subscriptions/:id/resume  → reactivar suscripción pausada
POST   /api/user-subscriptions/:id/force-renew → generar orden de renovación manual
POST   /api/user-subscriptions/trigger-weekly-deliveries → ejecutar job semanal manualmente

─── PLANES DE SUSCRIPCIÓN (solo admin) ──────────────────────
GET    /api/subscriptions                  → lista planes
POST   /api/subscriptions                  { name, price, frequencyWeeks, description? }
PUT    /api/subscriptions/:id              { name?, description?, price?, frequencyWeeks?, isActive? }

─── PRODUCTOS (solo admin) ──────────────────────────────────
GET    /api/products                       → lista todos (activos e inactivos)
POST   /api/products                       { name, price, description?, stock?, imageUrl? }
PUT    /api/products/:id                   { name?, description?, price?, stock?, imageUrl?, isActive? }
DELETE /api/products/:id                   → desactiva (isActive=false)

─── OPERADORES (solo admin) ─────────────────────────────────
GET    /api/operators                      → lista usuarios staff
POST   /api/operators                      { contact, firstName, password, lastName?, role? }

─── CONFIGURACIÓN (solo admin) ──────────────────────────────
GET    /api/config/operating-hours         → horarios por día
PUT    /api/config/operating-hours         { dayOfWeek, openTime?, closeTime?, deliveryStartTime?, deliveryEndTime?, isActive? }
GET    /api/config/delivery-zones          → zonas de entrega
POST   /api/config/delivery-zones          { name, price, isActive? }
PUT    /api/config/delivery-zones/:id      { name?, price?, isActive? }

  6. FLUJO DE ESTADOS DE PEDIDO (para el timeline visual)
================================================================================

pending_payment → paid → preparing → ready → delivering → delivered
                                                          ↘ rescheduled
                          (cualquier estado) → cancelled

El flujo normal para pedidos de suscripción semanal:
1. Se genera automáticamente con status "paid" (ya está pago mensualmente)
2. Armador se asigna → "preparing"
3. Armador confirma armado → "ready"
4. Repartidor se asigna → "delivering" (se notifica al cliente)
5. Repartidor confirma entrega → "delivered"

IMPORTANTE: en pedidos type="subscription" el total puede ser $0 (entregas
semanales cubiertas por el pago mensual). Mostrar el monto del plan mensual
en la sección de suscripción, no en la orden de entrega.

================================================================================
  7. FLUJO DE SUSCRIPCIÓN MENSUAL (para contexto del CRM)
================================================================================

1. Cliente contrata plan → se crea UserSubscription status="pending_payment"
2. Cliente paga → status="active", se programa primera entrega
3. Cada semana (automático) → se generan órdenes de entrega status="paid"
   → armadores y repartidores son notificados por WhatsApp
4. 3 días antes del vencimiento del mes → recordatorio por WhatsApp al cliente
5. Al vencer el período → se genera orden de renovación y se envía link de pago
6. Cliente paga renovación → nuevo período activo
7. Si no paga en 3 días de gracia → status="expired"
8. Admin puede pausar/cancelar/forzar renovación desde el CRM

  11. CONFIGURACIÓN INICIAL
================================================================================

1. Crear proyecto Vite:
   npx -y create-vite@latest frontend --template react

2. Instalar dependencias:
   cd frontend
   npm install react-router-dom axios @react-oauth/google recharts lucide-react
   npm install -D tailwindcss @tailwindcss/vite

3. Configurar Tailwind en vite.config.js:
   import tailwindcss from '@tailwindcss/vite'
   export default defineConfig({
     plugins: [react(), tailwindcss()],
   })

4. En index.css:
   @import "tailwindcss";

5. Variables de entorno (.env):
   VITE_API_URL=http://localhost:3000
   VITE_GOOGLE_CLIENT_ID=tu-client-id-aqui

6. Proxy en vite.config.js (para evitar CORS en desarrollo):
   server: {
     proxy: {
       '/api': 'http://localhost:3000'
     }
   }

================================================================================
  12. NOTAS IMPORTANTES
================================================================================

- El backend ya tiene CORS configurado para CRM_FRONTEND_URL (http://localhost:5173)
- La autenticación usa Google ID Tokens directamente (no JWT propio)
- El token de Google expira cada ~1 hora. Manejar el refresh silencioso
- Los IDs son UUID. Mostrar solo los primeros 8 caracteres en la UI
- Montos en pesos argentinos (ARS). Formatear con separador de miles
- Fechas en timezone America/Argentina/Buenos_Aires, formato dd/mm/yyyy
- El backend corre en puerto 3000, el frontend en 5173
- Las compras individuales de productos están DESHABILITADAS en el bot.
  No construir flujo de compra en el frontend; sí mantener la gestión de
  Productos en admin para tener los datos actualizados.
- Los pedidos de tipo "subscription" con total=0 son entregas semanales
  cubiertas por el pago mensual. Mostrarlo claramente en la UI.
- El scheduler del backend corre automáticamente:
  • 09:00 diario → recordatorio de renovación
  • 09:05 diario → expiración de suscripciones sin pago
  • Lunes 08:00 → generación de pedidos semanales + notificación a operadores
